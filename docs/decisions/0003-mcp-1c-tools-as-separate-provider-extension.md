# ADR-0003: Инструменты mcp-1c как отдельное расширение-провайдер

- Статус: accepted
- Дата: 2026-09-05
- Связанные документы: [ADR-0001](0001-client-mcp-provider-architecture.md), [Спека mcp-instruments](../specs/mcp-instruments.md), [Контракт провайдеров](../specs/client-mcp-providers.md)

## Контекст

В проекте есть два MCP-сервера для 1С:

- `client_mcp` (`exts/client-mcp`) — MCP-сервер внутри клиента 1С: транспорт, реестры, провайдеры, запуск из `/C`.
- `mcp-1c` (Go + HTTP-сервис, vendor/1c-mcp-HTTP+GO) — внешний сервер с 12 инструментами и 11 промптами:
  метаданные, запросы, компиляция/исполнение BSL, журнал регистрации, поиск по коду.

Пользователи обоих серверов получают разные наборы возможностей в одной базе. Поддерживать и развивать
две линии (Go-сервер отдельно, клиентский MCP отдельно) дороже, чем одну. Часть инструментов mcp-1c
(9 из 12) не требует ни Go, ни внешнего HTTP-сервиса: всё, что им нужно, доступно из BSL в контексте клиента.

## Решение

Перенести 9 инструментов и 11 промптов mcp-1c в отдельное расширение `mcp_instruments` (префикс `Мспи_`),
построенное как провайдер по архитектуре ADR-0001: подсистема `Инструменты_Мсп_Провайдеры`, четыре
клиентских модуля-провайдера (регистрация) и четыре серверных модуля (логика). Расширение подключается
к штатному MCP-серверу client_mcp без изменений в самом `client_mcp` и `test_client`.

Исходники — Designer XML, сборка конфигуратором по отдельному конфигу `v8project.mcp-instruments.yaml`
(в основном `v8project.yaml` EDT-формат; форматы смешивать нельзя). Контракты инструментов сохранены 1:1
с Go-источником (имена, схемы, JSON-ответы по `onec/types.go`); осознанные отклонения перечислены в спеке
`docs/specs/mcp-instruments.md`.

## Альтернативы

### 1. Встроить инструменты в состав client_mcp

Меньше артефактов сборки, но: расширение-ядро обрастает доменной логикой анализа метаданных и исполнения
кода, теряя роль инфраструктуры; каждое изменение набора инструментов ломает совместимость основной
поставки; правки затронули бы `exts/client-mcp` и `exts/test_client`, что план переноса явно запрещал.

### 2. Перенести всё, включая Go-зависимые инструменты

search_code (индексация исходников), bsl_syntax_help (данные Синтакс-помощника), reload_dump (внешний dump)
не имеют BSL-эквивалента в контексте клиента и требуют внешних артефактов. Их перенос увеличил бы объём
без гарантии контрактов, поэтому они оставлены за рамками; промпты очищены от упоминаний.

## Последствия

- Клиент 1С с расширениями client_mcp + mcp_instruments даёт 9 инструментов и 11 промптов mcp-1c без Go-сервера.
- Поиска по коду в этом наборе нет (см. альтернативу 2); промпты не ссылаются на неперенесённые инструменты.
- Набор инструментов управляется переключателями включённости штатного реестра провайдеров.
- Поддержка двух форматов исходников (EDT для основных наборов, Designer для mcp_instruments) закреплена
  двумя конфигами v8-runner; CI собирает mcp_instruments импортом из `exts/mcp-instruments/src`.
- Развитие инструментов mcp-1c и клиентского MCP теперь синхронно: контрактные изменения регистрируются
  в спеке mcp-instruments.
