# ADR-0004: REPL вместо validate_bsl_code

- Статус: accepted
- Дата: 2026-09-06
- Связанные документы: [ADR-0003](0003-mcp-1c-tools-as-separate-provider-extension.md), [Спека REPL](../specs/repl.md), [Спека mcp-instruments](../specs/mcp-instruments.md)

## Контекст

`validate_bsl_code` (порт `MCP_ПроверкаBSLPOST` из mcp-1c) дефектен: режим `execute`
исполняет тело метода через `Выполнить()` в контексте `Мсп_ИнструментыКодаСервер.ПроверитьКод`,
поэтому локальные переменные фрагмента затирают служебные переменные функции — «Поле объекта
не обнаружено» (зафиксировано в спеке mcp-instruments, отложено 2026-09-05). Проверить код
конфигурации в живой ИБ агенту нечем: `compile` проверяет только обёртку одного метода,
а инфраструктуры для итеративной работы с переменными нет.

Агенту нужна песочница: проверить фрагмент BSL против живой базы — выполнить, увидеть
значения, исправить, выполнить снова — без риска изменить данные.

## Решение

1. **Удалить `validate_bsl_code` полностью** (регистрация, обработчик, схема,
   `ПроверитьКод` и осиротевшие хелперы). Четыре промпта модуля кода не трогаем.
2. **REPL из трёх инструментов** `repl_create` / `repl_eval` / `repl_close`
   (контракт — [спека REPL](../specs/repl.md)): исполнение фрагмента в транзакции
   с **безусловным откатом** — база не меняется никогда, флагов подтверждения нет.
   Между eval живёт только `Состояние` (серверное временное хранилище).
3. **Отказ от вытеснения**: sync-исполнение без фоновых заданий и таймаутов. Долгий
   фрагмент блокирует endpoint до завершения; «чистый лист» — новый сеанс. Профиль принят
   осознанно: REPL-проверки короткие, а честный таймаут в 1С без убийства сеанса невозможен.
4. **Два движка**: операторный/выражения (`Выполнить`/`Вычислить` в обёртке с минимумом
   локальных переменных — это и есть изоляция контекста, которой не хватало старому коду)
   и модульный (компиляция EPF портом техники YaxUnit `ЮТРедакторОбработки` — для
   фрагментов с `Процедура`/`Функция`, которые `Выполнить()` не принимает).
5. **Состояние — во временном хранилище** с адресом-GUID: доказано YaXUnit
   (`ЮТКонтекстСлужебныйВызовСервера`), что ВХ хранит значения между серверными вызовами.
   Запись Состояния в ВХ — строго после отката транзакции.

## Альтернативы

### 1. Ремонт validate_bsl_code (изоляция контекста обёрткой)

Починило бы режим execute, но оставило бы контракт «одного метода»: нельзя исполнять
фрагменты операторов, нельзя накапливать переменные между вызовами, двухфлаговое
подтверждение (`allow_changes` + `confirm`) — сложный и рискованный интерфейс для агента.
Объём работы сопоставим с REPL при меньшей ценности.

### 2. Сохранить режим фиксации изменений за явными флагами

Отказано: любой путь «записать в базу из MCP-инструмента» — риск незапланированных
изменений данных агентом. Изменения конфигурации остаются за штатным процессом сборки
(unica/конфигуратор), не за REPL.

### 3. Таймауты/вытеснение через фоновые задания

Отказано: `Выполнить()`-фрагмент нельзя прервать изнутри сеанса; фоновое задание не даёт
доступа к Состоянию-ВХ клиентского вызова, а убийство зависшего задания не освобождает
endpoint. Sync-профиль проще и честнее.

## Последствия

- Набор инструментов mcp-instruments: 8 портов mcp-1c + 3 REPL-инструмента; `validate_bsl_code`
  исчезает из `tools/list` (breaking change для потребителей — отмечено в history).
- Агент получает итеративную проверку кода против живой ИБ: выражения, операторы,
  целые модули с вызовом экспортных методов; транзакционные вызовы в фрагментах
  принудительно вырезаются препроцессором.
- Добавляются активы: общий макет `Мспи_ШаблонОбработки` (бинарный шаблон EPF) и
  контейнер-код лицензии Apache-2.0 (порт из YaxUnit с атрибуцией).
- Ограничения приняты: `Сообщить()` не захватывается, Состояние недоступно module-фрагментам,
  битые ссылки после отката, блокировка endpoint долгими фрагментами.
