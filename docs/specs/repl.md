# Спецификация REPL 1C в mcp_instruments (repl_create / repl_eval / repl_close)

Песочница проверки кода BSL в живой ИБ. Каждый `repl_eval` исполняется в транзакции
с **безусловным откатом**: база не меняется никогда, ни при каком сочетании параметров.
Между eval одного сеанса помнятся только значения, положенные в `Состояние`. Замена
удалённого `validate_bsl_code` — см. [ADR-0004](../decisions/0004-repl-instead-of-validate-bsl-code.md).
Образец структуры контракта — `vendor/mcp_repl_bsl/docs/specs/repl.md` (OneScript-сервер;
совпадает только форма, не реализация).

Дом: расширение `exts/mcp-instruments`, модули `Мсп_ИнструментыREPLКлиент` (подсистема
`Инструменты_Мсп_Провайдеры`) и `Мсп_ИнструментыREPLСервер` (Server+ServerCall), общий
макет `Мспи_ШаблонОбработки` (бинарный шаблон EPF для движка модулей). Имена инструментов
английские snake_case, описания русские, ключи ответов английские.

## Инструменты

Все три инструмента возвращают structured content — JSON с полями ниже.

### `repl_create`

Создаёт новый REPL-сеанс. Параметров нет.

| Поле | Тип | Описание |
| --- | --- | --- |
| `repl_id` | string | Идентификатор сеанса: адрес временного хранилища (строка-UUID). Единственный handle для последующих вызовов. |

Сеанс — это адресованный уникальным идентификатором слот временного хранилища
на сервере со значением `Соответствие` (Состояние); `repl_id` — сам адрес.
Клиентского реестра нет: модуль-провайдер не хранит состояние (общим модулям
без контекста запрещены переменные уровня модуля). Сеансы не имеют лимита количества и
idle-таймаута; умирают вместе с сеансом 1С. «Забыть всё» = `repl_close` +
`repl_create`.

### `repl_eval`

Исполняет фрагмент BSL в сеансе.

Вход:

| Поле | Тип | Обяз. | Описание |
| --- | --- | --- | --- |
| `repl_id` | string | да | Идентификатор сеанса из `repl_create`. |
| `code` | string | да | Фрагмент BSL: выражение, операторы или текст модуля с подпрограммами. |
| `method` | string | нет | Имя экспортного метода для вызова после компиляции (только для module-фрагментов). |
| `arguments` | object | нет | Аргументы вызова `method` по имени; ключи обязаны совпадать с параметрами метода. |

Схема — закрытый объект (`additionalProperties: false`).

Выход (structured):

| Поле | Тип | Описание |
| --- | --- | --- |
| `status` | string | `ok` \| `error`. |
| `mode` | string | `expression` \| `statements` \| `module` — движок исполнения. |
| `value.has_value` | boolean | Есть ли возвращаемое значение. `false` для операторов без `Результат` и для module без `method`. |
| `value.type` | string | Имя типа значения (`Число`, `Строка`, `СправочникСсылка.Товары`, …). |
| `value.presentation` | string | Строковое представление, обрезанное до 4096 символов. |
| `value.json` | any | Типизированное JSON-представление для примитивов; для Массив/Структура/Соответствие — попытка сериализации в JSON; для остального поле опущено. |
| `error.kind` | string | `compile_error` \| `runtime_error` \| `session_not_found` \| `invalid_argument` \| `internal_error`. |
| `error.message` | string | Текст ошибки. |
| `error.line` | number | Номер строки (1-based, в координатах фрагмента), для `compile_error`, когда удалось извлечь. |
| `rolled_back` | boolean | Откачена ли транзакция обёртки. `false` — редкий случай: вырезание транзакционных вызовов что-то пропустило, и фрагмент сам закрыл транзакцию обёртки (см. страховку). |
| `duration_ms` | number | Длительность eval, мс. |

Кодов `timeout` / `worker_failed` / `repl_alive` и поля `messages` в контракте нет:
процессов и вытеснения нет, `Сообщить()` не захватывается.

### `repl_close`

Закрывает сеанс. Идемпотентен.

| Поле | Тип | Обяз. | Описание |
| --- | --- | --- | --- |
| `repl_id` | string | да | Идентификатор сеанса. |

Выход:

| Поле | Тип | Описание |
| --- | --- | --- |
| `repl_id` | string | Переданный идентификатор. |
| `closed` | boolean | `true`, если сеанс существовал и закрыт; `false`, если сеанса уже не было. |

Закрытие удаляет Состояние из временного хранилища сервера; повторный eval по закрытому
`repl_id` возвращает `session_not_found`.

## Коды прикладных ошибок

- неизвестный/закрытый `repl_id` при `repl_eval` → `session_not_found`;
- пустой `code`, пустой/нестроковый `repl_id`, некорректный `arguments`/`method` → `invalid_argument`;
- ошибка компиляции (включая EPF-движок) → `compile_error` (с `error.line`, если координата извлечена);
- ошибка исполнения → `runtime_error`;
- непредвиденное исключение обёртки → `internal_error`.

## Классификация фрагмента

Порядок проверки (первое совпадение выбирает движок):

1. `Процедура`/`Функция`/`Procedure`/`Function` на верхнем уровне (первая непустая строка
   вне строковых литералов и комментариев начинается с ключевого слова) → **module**.
2. Одиночный верхнеуровневый `=` с присваиваемой левой частью (имя переменной, обращение
   по индексу `Состояние["…"]` или свойство `Объект.Свойство`) → **statements**.
3. Иначе — проверка компиляции как выражение без исполнения: обёртка
   `Если Ложь Тогда` + `Результат = (<code>);` + `КонецЕсли;` через `Выполнить()`.
   Скомпилировалось → **expression**; ошибка компиляции → **statements**.

Эвристика «`=` = присваивание»: сравнение `А = Б` как выражение классифицируется в
statements и исполняется как присваивание — возвращаемого значения не будет. Это
зафиксированное поведение, не дефект. Двойной прогон исключён: классификационная проверка
идёт по мёртвой ветке и ничего не исполняет.

## Препроцессор: вырезание управления транзакциями

Перед исполнением (обоими движками: операторным фрагментом и текстом модуля EPF) из кода
удаляются вызовы `НачатьТранзакцию` / `ЗафиксироватьТранзакцию` / `ОтменитьТранзакцию`
и `BeginTransaction` / `CommitTransaction` / `RollbackTransaction`: построчный разбор;
строка, чей первый значимый токен — одно из ключевых слов (регистронезависимо), удаляется
целиком. Строковые литералы не трогаются (строки-продолжения `|…` и строки внутри кавычек
не начинаются с ключевого слова). Обёртка — единоличный владелец транзакции.

Страховка: после исполнения проверяется `ТранзакцияАктивна()`; если фрагмент каким-то
образом закрыл транзакцию обёртки (многострочный вызов, динамический `Выполнить` внутри
фрагмента), откат невозможен — в ответе `rolled_back = false`, транзакция уже закрыта
самим фрагментом. Имена `Выполнить`/`Вычислить` внутри фрагмента препроцессором
не перехватываются.

## Семантика исполнения

```
Исполнить(Адрес, Код, ИмяМетода, Аргументы):
  1. Состояние = ПолучитьИзВременногоХранилища(Адрес)  // Соответствие
  2. Код' = ВырезатьУправлениеТранзакциями(Код)
  3. Классификация: module | statements | expression
  4. НачатьТранзакцию()
  5. Исполнение движком по классификации
  6. Если ТранзакцияАктивна() → ОтменитьТранзакцию(); rolled_back = true
     Иначе rolled_back = false (вырезание пропустило вызов)
  7. ПоместитьВоВременноеХранилище(Состояние, Адрес)   // строго ПОСЛЕ отката
  8. Structured-ответ
```

- **Откат безусловный**: флагов подтверждения нет, изменений не «сохранить» нельзя.
- **Состояние и откат**: изменения Состояния в памяти (объекты, положенные
  `Состояние.Вставить(...)` или мутация элементов) переживают откат — движок помнит
  значения; записи в ИБ откатываются. Ссылки на откаченные объекты становятся битыми —
  штатно. Запись Состояния в ВХ выполняется после отката, поэтому даже при runtime-ошибке
  фрагмента Состояние сохраняет изменения, сделанные до ошибки.
- **Обёртка исполнителя** — отдельная процедура с минимумом локальных переменных:
  фрагмент видит только `Код` и `Состояние`. Коллизия имён переменных фрагмента с этими
  двумя — штатная ошибка исполнения фрагмента, так и задумано.

### Движок expression

`Вычислить(Код)` в процедуре-обёртке. Значение выражения возвращается напрямую.

### Движок statements

`Выполнить(Код)` в процедуре-обёртке со статической переменной `Результат` и маркером
(пустой GUID): переменная `Результат` присвоена фрагментом → её значение (`has_value=true`),
не присвоена → `has_value=false`. Прямой `Вычислить("Результат")` из динамических переменных
`Выполнить` не читается — потому маркер, а не вычисление.

### Движок module (EPF)

Фрагмент с подпрограммами компилируется во внешнюю обработку: из макета `Мспи_ШаблонОбработки`
(порт техники YaxUnit `ЮТРедакторОбработки`: контейнер внешней обработки unpack → подмена
текста модуля объекта `00ab4620-8498-4b18-a4f8-18b53138fcb5.0/text` → repack) и подключается
`ВнешниеОбработки.Подключить(ПоместитьВоВременноеХранилище(Данные))`.

- `method` задан → вызов экспортного метода обработанного объекта: соответствие ключей
  `arguments` параметрам метода (порт проверки из старого `ПроверитьКод`), вызов с
  передачей значений по имени; возвращаемое значение — в `value`. `method` не задан →
  только компиляция, `has_value=false`.
- Синтаксическая ошибка → `compile_error` с реальным номером строки фрагмента. Компиляция
  верифицируется `ВнешниеОбработки.Создать` до транзакции: `Подключить` модуль объекта
  не компилирует, ошибка всплыла бы runtime-ошибкой при создании.
- **Состояние фрагменту-модулю недоступно**: код исполняется в отдельном объекте внешней
  обработки, не в обёртке. Положить что-то в `Состояние` из module-фрагмента нельзя.

## Сериализация значения

| Тип значения | `value.json` |
| --- | --- |
| Число, Строка, Булево | типизированный JSON как есть |
| Дата | строка ISO-8601 (`XMLСтрока`) |
| Неопределено, NULL | `null` |
| Массив, Структура, Соответствие | попытка `ЗаписатьJSON`; при неудаче — поле опущено, только `type` + `presentation` |
| Ссылки и прочие типы | поле опущено, только `type` + `presentation` |

`presentation` — `Строка(Значение)`, обрезка до ~4096 символов.

## Ограничения (зафиксированы, не дефекты)

- **`Сообщить()` не захватывается**: в серверном вызове из BSL перехват вывода невозможен.
  Возвращайте значения выражением или через переменную `Результат`, а не `Сообщить`.
- **Долгий фрагмент блокирует MCP-endpoint** до завершения: модель исполнения sync, без
  фоновых заданий и вытеснения. «Чистый лист» вместо таймаута — `repl_close` + `repl_create`.
- **Состояние недоступно module-фрагментам** (отдельный объект исполнителя).
- **`Метаданные` во фрагменте — метаданные расширения `mcp_instruments`**, а не всей базы:
  `Метаданные.Справочники.Содержит(...)` не видит справочники конфигурации. Менеджеры
  (`Справочники.X`, `Документы.X`) и запросы видят всю базу — пользуйтесь ими.
- **Битые ссылки после отката** — объекты, записанные и откаченные, остаются в Состоянии
  как битые ссылки; обращение к их данным — runtime-ошибка.
- **Состояние живёт во временном хранилище сеанса 1С**: завершение сеанса (закрытие клиента,
  дисконнект) убивает все сеансы REPL.
- **Коллизия имён фрагмента со служебными переменными обёртки** (`Код`, `Состояние`,
  `Результат`-маркер — пустой GUID) — штатная ошибка компиляции или исполнения.

## Состав mcp-instruments после замены

Инструменты: 8 перенесённых из mcp-1c + `repl_create`/`repl_eval`/`repl_close`;
`validate_bsl_code` удалён. Промпты кода (`review_module`, `write_posting`,
`find_duplicates`, `1c_development_workflow`) не изменились.
