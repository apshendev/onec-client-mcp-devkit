# Стек и соглашения

Этот документ фиксирует только версии, структуру исходников, оформление BSL, политику версионирования.

## Стек

- `1С:Предприятие 8.3.27`, вариант языка `Русский` — весь код пишется на русском.
- Сборка и выгрузка исходников — `v8-runner` по конфигурации `v8project.yaml`: builder `DESIGNER`, workPath `build`, информационная база `File=build/ib`.
- Автотесты — YaXUnit (source-set `tests`, запуск через тест-менеджер).
- Транспорт MCP — внешняя компонента `AddIn.WebTransport.mcp`, поставляется в общем макете `Мсп_webTransport`; обновление макета — `scripts/update-web-transport.sh`.
- Прекоммит-хуки — `prek` (конфигурация `prek.toml`).

## Исходники

Четыре source-set'а (см. `v8project.yaml`):

| Source-set | Тип | Путь | Назначение |
| --- | --- | --- | --- |
| `client_mcp` | EXTENSION | `exts/client-mcp` | Основное расширение: MCP-сервер, транспорт, реестры, провайдеры |
| `test_client` | EXTENSION | `exts/test_client` | Тестовое расширение-«клиент» для приёмочных сценариев взаимодействия с MCP-сервером |
| `configuration` | CONFIGURATION | `fixtures/configuration` | Хост-конфигурация, в которую собираются расширения для сборки и тестов |
| `tests` | EXTENSION | `tests` | Тесты YaXUnit |

Раскладка и служебные каталоги:

- Исходники каждого source-set'а лежат в подкаталоге `src/` с подкаталогами по видам метаданных (`Configuration`, `CommonModules`, `CommonTemplates`, `Subsystems`, `CommonForms`, `CommonCommands`, `Roles`, `DataProcessors`, `CommonPictures`).
- Сборочные артефакты — в `build/` (в git не хранится): файлы `.cfe` для расширений, `.cf` для конфигурации.
- `uat/mcp-protocol/` — приёмочные тесты протокола MCP на python (`run.py`, `run-autostart.py`, сценарии в `scenarios.md`).
- `scripts/` — служебные скрипты: `update-web-transport.sh` обновляет макет внешней компоненты WebTransport.

## Оформление BSL и метаданных

### API Contracts
- Минимизировать нормализации и лишние преобразования данных.
- Нормализация считается явным сигналом сломанного контракта.
- Для публичного API не добавлять скрытые адаптеры или автонормализацию без явного подтверждения пользователя.
- Для служебного или внутреннего API не нормализовывать вход "на всякий случай"; если контракт неудобен или неверен, менять сам контракт и его callers.

### 1C App Module State
- Application module may contain only global variables and application event handlers.
- Global state should be stored in exported variables in the application module.
- Access to global state must be via getter/setter methods placed in a common module (not in the application module).

### Стиль BSL

- Для методов не добавляем префикс (например MCP).
- Каждому экспортному методу непосредственно предшествует комментарий, поясняющий его назначение. Комментарий экспортного метода с параметрами содержит секцию «Параметры:» со строкой «Имя - Тип» для каждого параметра; экспортная функция — секцию «Возвращаемое значение:» с типизированной строкой (#std453).
- Каждый метод модуля находится ровно внутри одной пары `#Область` … `#КонецОбласти`; методы вне областей не допускаются.
- Каждому экспортному методу предшествует комментарий; каждый метод — ровно в одной области `#Область` … `#КонецОбласти`.
- Суффиксы общих модулей — по BSP-конвенции: `…Клиент`, `…Сервер`, `…КлиентСервер`, `…ВызовСервера`, `…ПовтИсп`, `…Переопределяемый`.
- Текст пользовательского интерфейса и комментарии — на русском; при добавлении текста соответствуй окружающим файлам.
- Язык русский; максимальная длина строки **140**; когнитивная сложность ≤ 20, цикломатическая ≤ 25.
- Отключить правило BSLLS инлайн: `// BSLLS:<RuleName>-off`.
