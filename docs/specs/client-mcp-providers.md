# client-mcp: контракт провайдеров

Спека разработчика: как расширять функциональность MCP-сервера `client_mcp` — поставлять инструменты, ресурсы и промпты через провайдеров. Про внутренности запуска web-сервиса и перенос механизма — [`client-mcp-internals.md`](client-mcp-internals.md); краткое пользовательское введение — [`../extending.md`](../extending.md); архитектура провайдеров — [ADR-0001](../decisions/0001-client-mcp-provider-architecture.md).

Соглашение о координатах: пути вида `Путь/Файл.bsl:строка` указаны относительно `exts/client-mcp/src/`, если не указан полный путь от корня репозитория. Номера строк могут смещаться при правках — при расхождении ориентируйтесь на имя метода.

## B. Расширение функционала

### B.1 Модель провайдеров

Провайдер — общий модуль, который поставляет инструменты, ресурсы и промпты. Явной регистрации в коде не требуется: провайдеры обнаруживаются по метаданным.

Обнаружение (сервер):

- `CommonModules/Мсп_МетаданныеСервер/Module.bsl:3` — `Провайдеры()`: собирает описания `{Имя, Тип}`.
- `CommonModules/Мсп_МетаданныеСервер/Module.bsl:31` — `ПодсистемыПровайдеры()`: точка поиска — подсистема `Мсп_Провайдеры` и любые подсистемы с суффиксом `_Мсп_Провайдеры` (у которых выключен `ВключатьВКомандныйИнтерфейс`). Это позволяет конфигурации-хосту или соседнему расширению завести свою область провайдеров, не трогая `client_mcp`.
- `CommonModules/Мсп_МетаданныеСервер/Module.bsl:19` — `ДобавитьПровайдеровПодсистемы()`: из состава подсистемы общие модули попадают в реестр с типом `ОбщийМодуль`, обработки — с типом `Обработка`.

Исполнение (клиент):

- `CommonModules/Мсп_ПровайдерыКлиент/Module.bsl:4` — `ЗарегистрироватьПровайдеров()`: вызывается при инициализации сервера (`Мсп_Сервер.Инициализировать`, `CommonModules/Мсп_Сервер/Module.bsl:5`) и при начальной загрузке реестров компоненты.
- `CommonModules/Мсп_ПровайдерыКлиент/Module.bsl:36` — `МодульПровайдера()`: сейчас исполняются только провайдеры типа `ОбщийМодуль` (`Вычислить(Имя)`); для остальных типов запись об ошибке в лог.

Регистрация провайдера — `CommonModules/Мсп_ПровайдерыКлиент/Module.bsl:17` — см. B.2.

### B.2 Канонический контракт

```bsl
Процедура Зарегистрировать(ИсточникРегистрации) Экспорт
```

Контракт вызова (реализация — `CommonModules/Мсп_ПровайдерыКлиент/Module.bsl:17`):

1. Поднимается флаг `РегистрацияПровайдераВыполняется` — на время регистрации планирование синхронизации реестров отключено (глухой guard в `Мсп_ТранспортРеестрыКлиент.ЗапланироватьСинхронизацию`, `CommonModules/Мсп_ТранспортРеестрыКлиент/Module.bsl:321`), все регистрации одного провайдера схлопнутся в один проход.
2. Вызывается `Зарегистрировать` модуля провайдера; параметр `ИсточникРегистрации` — имя провайдера. Передавайте его в каждый вызов `Мсп_Сервер.Зарегистрировать*` — это ключ, по которому работает `ОтменитьРегистрации` и переключатели включённости в форме.
3. Флаг сбрасывается, планируется синхронизация реестров с компонентой (уведомление `tools/list_changed` и аналоги — см. `client-mcp-internals.md`, A.5).
4. Исключение в `Зарегистрировать` не валит сервер: флаг сбрасывается, ошибка пишется в лог (`Мсп_ЛогированиеКлиент.Ошибка`), остальные провайдеры регистрируются дальше.

Полный компилируемый пример провайдера (инструмент + ресурс + промпт). Модуль включается в подсистему `Мсп_Провайдеры` (или `*_Мсп_Провайдеры`):

```bsl

#Область ПрограммныйИнтерфейс

// Регистрирует инструменты, ресурсы и промпты провайдера.
Процедура Зарегистрировать(ИсточникРегистрации) Экспорт
	Мсп_Сервер.ЗарегистрироватьИнструмент(Мсп_Сервер.НовыйИнструмент(
		"calc_total",
		"Складывает два числа и возвращает сумму.",
		СхемаИнструмента(),
		Новый ОписаниеОповещения("ОбработатьИнструмент", Мсп_МойПровайдерКлиент)),
		ИсточникРегистрации);

	Мсп_Сервер.ЗарегистрироватьРесурс(Мсп_Сервер.НовыйРесурс(
		"myscheme://status",
		"Статус",
		"Текущий статус подсистемы.",
		"application/json",
		Новый ОписаниеОповещения("ОбработатьРесурс", Мсп_МойПровайдерКлиент)),
		ИсточникРегистрации);

	Мсп_Сервер.ЗарегистрироватьПромпт(Мсп_Сервер.НовыйПромпт(
		"daily_report",
		"Черновик ежедневного отчёта.",
		АргументыПромпта(),
		Новый ОписаниеОповещения("ОбработатьПромпт", Мсп_МойПровайдерКлиент)),
		ИсточникРегистрации);
КонецПроцедуры

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

// Обрабатывает вызов инструмента.
//
// Параметры:
//  Запрос - Структура - Запрос инструмента:
//   * Аргументы - Структура - Аргументы вызова.
//   * Контекст - Структура - Контекст вызова.
//
// Возвращаемое значение:
//  Структура - Результат вызова.
Функция ОбработатьИнструмент(Запрос, ДополнительныеПараметры) Экспорт
	Сумма = Запрос.Аргументы.a + Запрос.Аргументы.b;
	Возврат Мсп_Результаты.JSON(Новый Структура("Сумма", Сумма));
КонецФункции

// Обрабатывает чтение ресурса.
//
// Возвращаемое значение:
//  Структура - Результат чтения ресурса.
Функция ОбработатьРесурс(Запрос, ДополнительныеПараметры) Экспорт
	Возврат Мсп_Результаты.Ресурс("myscheme://status", Новый Структура("Состояние", "работает"));
КонецФункции

// Обрабатывает получение промпта.
//
// Возвращаемое значение:
//  Структура - Результат с сообщениями промпта.
Функция ОбработатьПромпт(Запрос, ДополнительныеПараметры) Экспорт
	Тема = Мсп_Коллекции.Свойство(Запрос.Аргументы, "Тема", "без темы");
	Сообщения = Новый Массив;
	Сообщения.Добавить(Мсп_Результаты.ТекстовыйПромпт("Составь отчёт по теме: " + Тема, "user"));
	Возврат Мсп_Результаты.Промпт(Сообщения);
КонецФункции

Функция СхемаИнструмента()
	Свойства = Новый Структура;
	Свойства.Вставить("a", Мсп_СхемаПараметров.НовоеСвойствоСхемы("number", "Первое слагаемое."));
	Свойства.Вставить("b", Мсп_СхемаПараметров.НовоеСвойствоСхемы("number", "Второе слагаемое."));
	Требуемые = Новый Массив;
	Требуемые.Добавить("a");
	Требуемые.Добавить("b");
	Возврат Мсп_СхемаПараметров.НовыйСхемаОбъекта(Свойства, Требуемые);
КонецФункции

Функция АргументыПромпта()
	Аргументы = Новый Массив;
	Аргументы.Добавить(Новый Структура("name,description,required", "Тема", "Тема отчёта.", Истина));
	Возврат Аргументы;
КонецФункции

#КонецОбласти
```

Обработчики получают структуру запроса (`Аргументы`, `Контекст`) и возвращают результат, упакованный `Мсп_Результаты` (раздел B.6). Образцы в исходниках: встроенный `Мсп_ИнструментИнфоИБКлиент` (`CommonModules/Мсп_ИнструментИнфоИБКлиент/Module.bsl:4`) и тестовый провайдер на 14 инструментов `exts/test_client/src/CommonModules/Мсп_ИнструментТестКлиент/Module.bsl:4`.

### B.4 Расширенные режимы вызова

**Отложенный ответ (deferred).** Задаётся пятым параметром `НовыйИнструмент(..., ОтложенныйОтвет = Истина)` (`CommonModules/Мсп_Сервер/Module.bsl:25`). Обработчик возвращает `Неопределено` (`Мсп_ПротоколКлиент.ВызватьОтложенныйОбработчик` — `CommonModules/Мсп_ПротоколКлиент/Module.bsl:73`), транспорт не отвечает сразу; провайдер завершает вызов позже:

- `Мсп_Сервер.ЗавершитьВызовИнструментаУспешно` (`CommonModules/Мсп_Сервер/Module.bsl:285`);
- `Мсп_Сервер.ЗавершитьВызовИнструментаСОшибкой` (`CommonModules/Мсп_Сервер/Module.bsl:300`).

**Task-режим.** Долгие операции: MCP-клиент вызывает инструмент с `executionMode = task` и `taskId`; ответ отправляется по завершении, клиент может отменить задачу событием `MCP_TASK_CANCELLED` (маршрут — `client-mcp-internals.md`, A.6). Завершение и статус:

- `Мсп_Сервер.ЗавершитьЗадачуУспешно` / `ЗавершитьЗадачуСОшибкой` (`CommonModules/Мсп_Сервер/Module.bsl:314`, `:324`), низкоуровнево — `Мсп_ЗадачиКлиент` (`CommonModules/Мсп_ЗадачиКлиент/Module.bsl:8`, `:29`, `:49`);
- `Мсп_Сервер.УстановитьСтатусЗадачи` (`CommonModules/Мсп_Сервер/Module.bsl:334`);
- проверка отмены в длительном цикле: `Мсп_Сервер.ЗадачаОтменена` (`CommonModules/Мсп_Сервер/Module.bsl:367`), сброс отметки — `ОчиститьОтменуЗадачи` (`:375`).

Ограничение: публичный `НовыйИнструмент` всегда создаёт `РежимВыполнения = "sync"` (`CommonModules/Мсп_Сервер/Module.bsl:40`); task-дескриптор создаётся внутренним `Мсп_ПротоколКлиент.НовыйОписаниеИнструмента(Имя, Описание, Схема, "task")` (`CommonModules/Мсп_ПротоколКлиент/Module.bsl:216`; образец — `tests/src/CommonModules/ОМ_ПротоколКлиент/Module.bsl:79`). Вызов task-инструмента в sync-режиме и наоборот отклоняется валидацией (`CommonModules/Мсп_ПротоколКлиент/Module.bsl:598`).

**Прогресс.** `Мсп_Сервер.УведомитьОПрогрессе(ТокенПрогресса, Значение, Сообщение)` (`CommonModules/Мсп_Сервер/Module.bsl:356`) — отправляет notification `notifications/progress`; токен берётся из `_meta.progressToken` запроса. Для задач — `УведомитьОПрогрессеЗадачи` (`CommonModules/Мсп_Сервер/Module.bsl:345`, реализация `CommonModules/Мсп_ЗадачиКлиент/Module.bsl:94`).

### B.6 Результаты

Упаковка `Мсп_Результаты`:

| Метод | Строка | Формат |
| --- | --- | --- |
| `Текст(ТекстРезультата)` | `CommonModules/Мсп_Результаты/Module.bsl:3` | `{content: [{type: "text", text}]}` |
| `JSON(Данные)` | `CommonModules/Мсп_Результаты/Module.bsl:9` | `Текст(Сериализовать(Данные))` |
| `Ресурс(URI, Данные, MimeType = "application/json")` | `CommonModules/Мсп_Результаты/Module.bsl:13` | `{contents: [{uri, text, mimeType}]}`; JSON-MIME сериализует данные, иначе данные приводятся к строке |
| `Промпт(Сообщения)` | `CommonModules/Мсп_Результаты/Module.bsl:25` | `{messages: [...]}` |
| `ТекстовыйПромпт(ТекстПромпта, Роль = "user")` | `CommonModules/Мсп_Результаты/Module.bsl:29` | Одно текстовое сообщение промпта |

Правило упаковки результата инструмента на runtime-уровне: значение `Строка` уходит как `content[0].text` без изменений; нестроковое значение сериализуется в JSON (см. [`../extending.md`](../extending.md)). Помощники чтения ресурсов для провайдеров — `Мсп_РесурсыКлиент.РезультатРесурса` (`CommonModules/Мсп_РесурсыКлиент/Module.bsl:12`).

### B.7 Legacy: `ЗарегистрироватьИнструменты() Экспорт` (удалён)

Контракт v1 (до переработки): провайдер экспортировал `Процедура ЗарегистрироватьИнструменты() Экспорт` без параметров. Регистратор вызывал её на модуле провайдера, внутри провайдер сам вызывал `Мсп_Сервер.ЗарегистрироватьИнструмент(...)` без источника регистрации. Fallback-механика «вызвать `ЗарегистрироватьИнструменты/Ресурсы/Промпты`, если нет `Зарегистрировать`» удалена коммитом `c614113` («fix: align mcp registration contracts»); динамическая синхронизация реестров (автоматический push изменений в компоненту и `list_changed`) добавлена коммитом `4bb20e0` («Add dynamic registry synchronization»). Вместе они заменили v1 на единый контракт `Зарегистрировать(ИсточникРегистрации)`.

Миграция v1 → v2:

| v1 (удалён) | v2 (актуальный) |
| --- | --- |
| `Процедура ЗарегистрироватьИнструменты() Экспорт` | `Процедура Зарегистрировать(ИсточникРегистрации) Экспорт` |
| Без параметров; источник регистрации не отслеживался | Параметр `ИсточникРегистрации` передаётся в каждый `Зарегистрировать*` |
| `Мсп_Сервер.ЗарегистрироватьИнструмент(Описание)` | `Мсп_Сервер.ЗарегистрироватьИнструмент(Описание, ИсточникРегистрации)` |
| Изменения требовали перезапуска клиента | `ОтменитьРегистрации(ИсточникРегистрации)` и повторная `Зарегистрировать` на живом сервере; реестры синхронизируются автоматически (A.5 в [`client-mcp-internals.md`](client-mcp-internals.md)) |

### B.8 Диагностика

- **Логирование** — `Мсп_ЛогированиеКлиент`: уровни `Отладка` (`CommonModules/Мсп_ЛогированиеКлиент/Module.bsl:7`), `Информация` (`:15`), `Важно` (`:23`), `Ошибка` (`:31`); параметры — `УстановитьПараметрыЛогирования` (`:49`). Через командную строку `/C`: ключи `log`, `logLevel`, `logFile` (`ПрименитьПараметрыЗапуска`, `CommonModules/Мсп_ЛогированиеКлиент/Module.bsl:69`).
- **Форма `Мсп_УправлениеMCP`** — списки зарегистрированных инструментов/ресурсов/промптов, переключатели включённости, запуск/остановка сервера, настройки логирования (`CommonForms/Мсп_УправлениеMCP/Module.bsl:62`–`:116`, `:118`).
- **Проверка, что провайдер подхватился**: (1) сервер запущен; (2) `tools/list` (или списки формы) содержат инструменты провайдера; (3) в логе нет записей об ошибке его `Зарегистрировать` (см. B.2, п. 4). Если провайдера нет в списках — проверить, что модуль включён в подсистему `Мсп_Провайдеры`/`*_Мсп_Провайдеры` (B.1).
