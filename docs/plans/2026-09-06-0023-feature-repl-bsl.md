# План: REPL 1C в mcp-instruments (замена validate_bsl_code)

Дата: 2026-09-06. Источник: grilling-сессия (полная, фронт закрыт). Референс контракта: `vendor/mcp_repl_bsl` (OneScript, только как образец контракта, не реализации).

## Контекст и цель

`validate_bsl_code` дефектен: режим execute исполняет тело метода через `Выполнить()` в контексте `Мсп_ИнструментыКодаСервер.ПроверитьКод`, локальные переменные фрагмента затирают служебные переменные функции → «Поле объекта не обнаружено» (`docs/specs/mcp-instruments.md:76–79`).

Вместо ремонта — полноценный REPL: **песочница проверки кода в живой ИБ**. Каждый eval исполняется в транзакции с безусловным откатом — база не меняется никогда. Между eval помнятся только переменные (`Состояние`). Вытеснения нет и не будет: вместо таймаута — «чистый лист» (новый сеанс).

## Зафиксированные решения (из grilling, не пересматривать)

| Тема | Решение |
| --- | --- |
| Судьба `validate_bsl_code` | Удалить полностью. 4 промпта в том же модуле (`review_module`, `write_posting`, `find_duplicates`, `1c_development_workflow`) остаются |
| Дом | `exts/mcp-instruments`: новые `Мсп_ИнструментыREPLКлиент` (в подсистеме `Инструменты_Мсп_Провайдеры`) + `Мсп_ИнструментыREPLСервер` (Server+ServerCall) + модуль-обёртка исполнителя с минимумом локальных переменных |
| Контракт | Три инструмента `repl_create` / `repl_eval` / `repl_close`. Без reset, без лимита сеансов, без idle-таймаута. `repl_close` идемпотентен. Сеансы умирают с перезапуском клиента 1С. «Забыть всё» = `repl_close` + `repl_create` |
| Модель исполнения | Sync, без фоновых заданий, без вытеснения. Долгий фрагмент блокирует MCP-endpoint до завершения — принятый профиль |
| Запись в ИБ | Каждый eval в транзакции с **безусловным откатом**: НИЧЕГО не сохраняется. Изменения переменных в памяти (движок помнит) переживают откат; ссылки на откаченные объекты становятся битыми — штатно |
| Состояние | Серверное временное хранилище: `repl_create` создаёт адрес ВХ и `Соответствие`-Состояние; клиентский реестр `repl_id → адрес`. Запись Состояния обратно в ВХ — строго ПОСЛЕ отката транзакции |
| Движок операторов/выражений | Эвристика: верхнеуровневый одиночный `=` с присваиваемой левой частью → операторы; иначе попытка `Вычислить` (выражение), при неудаче компиляции — `Выполнить` (операторы). Двойная попытка безопасна: транзакция откатывает побочные эффекты |
| Возврат значения | Выражение → значение напрямую. Операторы → после исполнения `Вычислить("Результат")` в `Попытке`: присвоено → значение, иначе `has_value=false` |
| Движок модулей | Фрагмент с `Процедура`/`Функция` на верхнем уровне → компиляция во внешнюю обработку (порт техники `ЮТРедакторОбработки`: шаблон EPF в расширении, подмена текста модуля, `ВнешниеОбработки.Подключить`) + опциональный вызов экспортного метода (`method`, `arguments` — порт сериализации аргументов из `ПроверитьКод`). `compile_error` с реальными номерами строк. Состояние фрагменту-модулю недоступно (отдельный объект) — документировать |
| Вложенные транзакции | Препроцессор **принудительно вырезает** из фрагмента все вызовы управления транзакцией: `НачатьТранзакцию` / `ЗафиксироватьТранзакцию` / `ОтменитьТранзакцию` + англ. `BeginTransaction` / `CommitTransaction` / `RollbackTransaction`. Внутри строковых литералов не трогать. Применяется к обоим движкам (операторам и тексту модуля перед вшиванием в EPF). Обёртка — единоличный владелец транзакции. Страховка после исполнения: `ТранзакцияАктивна()`; если вдруг не активна (вырезание пропустило) — откат невозможен, в ответе `rolled_back=false` |
| Сериализация значения | Примитивы (число/строка/булево/дата/Неопределено) → типизированный JSON; Массив/Структура/Соответствие → попытка JSON, при неудаче — только представление; ссылки и остальное → тип + представление. `presentation` урезается до ~4096 символов |
| `Сообщить()` | Не захватывается (в серверном вызове из BSL невозможно). В описании `repl_eval` — инструкция агенту: возвращать значения выражением/`Результат`, а не `Сообщить` |
| Ответ `repl_eval` | Structured: `{status, mode: expression\|statements\|module, value{has_value, type, presentation, json?}, error{kind, message, line?}, rolled_back, duration_ms}`. Коды ошибок: `compile_error / runtime_error / session_not_found / invalid_argument / internal_error`. `timeout` / `worker_failed` / `repl_alive` в контракте НЕТ (нет процессов, нет вытеснения). Ключи английские, имена инструментов англ. snake_case, описания русские |
| Установленные факты (не риски) | `Выполнить()` — только плоский код, подпрограммы не допускает (маршрутизация на EPF-движок). ВХ хранит значения между серверными вызовами (доказано YaXUnit `ЮТКонтекстСлужебныйВызовСервера`). Коллизия имён переменных фрагмента со служебными переменными обёртки = штатная ошибка исполнения фрагмента, так и задумано |
| Git | Новая ветка **от текущего HEAD**, не от master |

## Архитектура (целевая)

```
MCP-клиент
  └─ repl_create ──► Мсп_ИнструментыREPLКлиент: gen repl_id; серверный вызов СоздатьСеанс()
                          └─ Сервер: Адрес = ПоместитьВоВременноеХранилище(Новый Соответствие, Новый УникальныйИдентификатор())
                       клиентский реестр[repl_id] = {адрес}
  └─ repl_eval ───► Мсп_ИнструментыREPLКлиент: валидация, адрес из реестра
                          └─ Сервер Исполнить(repl_id, code, method?, arguments?):
                               1. Состояние = ПолучитьИзВременногоХранилища(Адрес)
                               2. Код' = ВырезатьУправлениеТранзакциями(Код)
                               3. Классификация: module | statements | expression
                               4. НачатьТранзакцию()
                               5. Исполнение (движок по классификации)
                               6. Если ТранзакцияАктивна() → ОтменитьТранзакцию(); rolled_back=true
                                  Иначе rolled_back=false (пропущено вырезание)
                               7. ПоместитьВоВременноеХранилище(Состояние, Адрес)  ← после отката
                               8. Structured-ответ
  └─ repl_close ──► удаление из реестра; идемпотентен
```

Классификация фрагмента:
- `Процедура`/`Функция`/`Procedure`/`Function` на верхнем уровне (вне строковых литералов) → **module**.
- Одиночный верхнеуровневый `=` с присваиваемой левой частью (имя/индекс/свойство) → **statements**.
- Иначе попытка `Вычислить` → **expression**; не скомпилировалось → `Выполнить` → **statements**.

### Шаг 2. Активы EPF-движка
Порт техники `tests/src/CommonModules/ЮТВнешниеОбработкиСлужебныйСервер` + обработки `ЮТРедакторОбработки` в `exts/mcp-instruments`:
1. Шаблон EPF-бинарника (ОбщийМакет расширения mcp-instruments) с идентификатором модуля-объекта.
2. Серверная функция `СкомпилироватьМодуль(ТекстМодуля)`: загрузить шаблон, подменить текст модуля, вернуть двоичные данные; `ПодключитьОбработку(ТекстМодуля)` → `ВнешниеОбработки.Подключить(ПоместитьВоВременноеХранилище(Данные))`.

**Критерий:** из внешнего кода (теста) `ПодключитьОбработку("Функция Привет() Экспорт Возврат 1 КонецФункции")` подключает обработку; синтаксическая ошибка в тексте модуля даёт исключение с номером строки.

### Шаг 3. Серверный модуль `Мсп_ИнструментыREPLСервер`
1. `СоздатьСеанс()` → адрес ВХ + пустое Состояние.
2. `Исполнить(Адрес, Код, ИмяМетода, Аргументы)`:
   - препроцессор вырезания транзакционных вызовов (RU+EN, построчный разбор с пропуском строковых литералов; удаляется весь оператор вызова);
   - классификация (module/statements/expression);
   - транзакционная обёртка с безусловным откатом и страховкой `ТранзакцияАктивна()`;
   - движок module: `ПодключитьОбработку` + опциональный вызов экспортного метода (порт разбора `arguments` из `ПроверитьКод`); compile-ошибка → `compile_error` с номером строки;
   - движок expression/statements: `Выполнить`/`Вычислить` в процедуре-обёртке с минимумом локальных переменных; после `Выполнить` — `Вычислить("Результат")` в `Попытке`;
   - запись Состояния в ВХ после отката;
   - сериализация значения (примитивы → JSON; коллекции → попытка JSON; остальное → тип+представление, обрезка ~4096);
   - structured-ответ по контракту.
3. Обёртка исполнителя — отдельная процедура; имена служебных переменных свести к минимуму (кандидаты: `Код`, `Состояние`).

**Критерий:** юнит-проверки шага 5 проходят; ручной прогон через тестовый вызов: `Т = Справочники.Товары.СоздатьЭлемент(); Т.Записать();` — после eval в базе объекта нет, `Т` в Состоянии присутствует (битая ссылка при следующем обращении — штатно).

### Шаг 4. Клиентский модуль + удаление старого инструмента
1. `Мсп_ИнструментыREPLКлиент.Зарегистрировать`: три инструмента со схемами (`repl_eval`: `repl_id`+`code` обязательны, `method`+`arguments` опциональны; `additionalProperties: false`); описания русские, включая инструкцию «возвращайте значения, а не Сообщить» и «НИЧЕГО не сохраняется, база не меняется».
2. Клиентский реестр сеансов (переменная уровня клиентского модуля): `repl_id → адрес ВХ`; `repl_close` идемпотентен (закрытого сеанса → `{closed: false}`); eval несуществующего → `session_not_found`.
3. Удалить из `Мсп_ИнструментыКодаКлиент` регистрацию `validate_bsl_code`, обработчик, схему (промпты не трогать); из `Мсп_ИнструментыКодаСервер` — `ПроверитьКод` и осиротевшие хелперы сериализации.

**Критерий:** `tools/list` живого сервера содержит `repl_create/repl_eval/repl_close`, не содержит `validate_bsl_code`, все 4 промпта на месте.

### Шаг 5. Автотесты (YaxUnit, расширение `tests`)
Серверные тесты нового контура:
1. Классификация: выражение / `А = 5` → statements / модуль → module.
2. `Результат`: присвоен → значение; не присвоен → `has_value=false`.
3. Откат: запись справочника внутри eval → после eval объекта нет в базе.
4. Состояние: два последовательных `Исполнить` в одном сеансе — переменная из первого видна во втором.
5. Вырезание транзакций: фрагмент с `НачатьТранзакцию(); … ЗафиксироватьТранзакцию();` — вызовы удалены, транзакция обёртки не нарушена, данные откачены.
6. EPF-движок: валидный модуль compiles; синтаксическая ошибка → `compile_error` с номером строки; вызов экспортного метода с аргументами → результат.
7. Ошибки: `session_not_found` (eval закрытого сеанса), `invalid_argument` (пустой `code`).

**Критерий:** все тесты зелёные в прогоне YaxUnit через `unica.runtime.execute` (applied, `dryRun: false`); полный `validate syntax-check` НЕ запускать (запрещён AGENTS.md) — только точечная валидация затронутых модулей.

### Шаг 6. Live-тест (`.scratch/live-test`)
