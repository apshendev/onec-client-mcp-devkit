## 1. Контекст

mcp-1c — MCP-сервер из Go-бинарника (stdio-транспорт) и 1С-расширения `MCP_HTTPService` с HTTP-сервисом `MCPService`: вся серверная логика лежит в одном модуле `vendor/1c-mcp-HTTP+GO/extension/src/HTTPServices/MCPService/Ext/Module.bsl` (1824 строки). Протокольная часть (Go, stdio, прокси-гигиена, bleve-индекс, installer) не переносится — переносится только содержательный слой: 9 инструментов с BSL-реализацией и 11 промптов.

**Формат исходников (правка 2026-09-05, по решению пользователя):** новый source-set `exts/mcp-instruments` ведётся в формате Designer XML (`src/Configuration.xml` и т.п.), сборка — только конфигуратором (v8-runner, builder IBCMD/DESIGNER); EDT CLI локально не используется и не требуется. Существующие наборы `client_mcp`, `test_client`, `configuration`, `tests` остаются в EDT-формате. Формат исходников глобален для конфига v8-runner, поэтому `mcp_instruments` зарегистрирован в отдельном конфиге `v8project.mcp-instruments.yaml` (format: DESIGNER, ИБ `build/ib-mci`, минимальная конфигурация-хост `mci_host` в `.scratch/mcp-instruments/host/src`); CI импортирует набор напрямую в полную хост-конфигурацию.

В devkit MCP-сервер живёт внутри клиента 1С (расширение `client_mcp`, внешний транспорт `AddIn.WebTransport.mcp`). Провайдер — клиентский общий модуль в подсистеме `Мсп_Провайдеры` или любой подсистеме верхнего уровня с суффиксом `_Мсп_Провайдеры` (обнаружение: `exts/client-mcp/src/CommonModules/Мсп_МетаданныеСервер/Module.bsl:31`). Обработчики исполняются на клиенте, поэтому серверные данные достаём парным серверным модулем (прямой вызов, как `&НаСервере` в `Мсп_УправлениеMCP`).
